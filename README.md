# P Smart Wallet 888

เวอร์ชันปัจจุบัน **V1.4.5** ดูรายละเอียดแต่ละรอบได้จากปุ่มประวัติการอัปเดตใน MENU

เว็บแอปบันทึกรายรับ-รายจ่ายส่วนตัว สำหรับนักเรียน นักศึกษา และวัยเริ่มทำงาน
เน้นบันทึกไว ดูสรุปเข้าใจง่าย และเก็บข้อมูลไว้ในเครื่องผู้ใช้เท่านั้น

## วิธีเปิดใช้งาน

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ **ห้ามดับเบิลคลิกไฟล์ `index.html` โดยตรง** เพราะเบราว์เซอร์
บล็อก ES modules บน `file://` และระบบเข้ารหัสรหัสผ่านต้องการ secure context

```bash
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

ถ้าจะเผยแพร่จริง ใช้ GitHub Pages หรือ static host อะไรก็ได้ที่เสิร์ฟผ่าน https
Service Worker ที่ทำให้ใช้งานออฟไลน์ได้ก็ต้องการ secure context เหมือนกัน
คือ https หรือ localhost เท่านั้น ถ้าเปิดจากที่อื่นแอปจะทำงานตามปกติแต่ไม่มีความสามารถออฟไลน์

## หน้าจอหลัก

| หน้า | ทำอะไร |
|---|---|
| โฮม | หมวดที่ปักหมุดไว้สำหรับบันทึกด่วน ปฏิทินรายการประจำ ภาพรวมเดือนนี้ ยอดคงเหลือสะสม รายการล่าสุด สถานะงบประมาณ รายการฟีเจอร์ และข้อมูลผู้ใช้ |
| บันทึก | เลือกรายรับ/รายจ่าย กรอกจำนวนเงิน เลือกหมวดหมู่ ใส่โน้ต เลือกวันที่ (ย้อนหลังได้ 60 วัน) |
| สถิติ | สลับมุมมอง วัน/สัปดาห์/เดือน/ปี พร้อมกราฟวงกลม 3 มิติ ยอดคงเหลือ breakdown ตามหมวดหมู่ และปุ่มออกรายงานสรุป |
| วางแผน | ตั้งงบประมาณรายเดือน ตั้งรายการประจำที่เกิดซ้ำ และตั้งเป้าหมายการออมเงิน |

## ระบบงบประมาณและการแจ้งเตือน

ตั้งเพดานการใช้จ่ายได้ทั้งรายหมวด และงบรวมทั้งเดือน แยกตามกระเป๋า
งบเป็นแบบต่อเดือนและใช้ซ้ำทุกเดือน ไม่ต้องตั้งใหม่

ระดับการเตือนมีสามขั้น

| ระดับ | เมื่อไร | สี |
|---|---|---|
| ยังอยู่ในงบ | ต่ำกว่า 70% | เขียว |
| ใกล้เกินงบ | 70% ถึงต่ำกว่า 100% | เหลือง |
| เกินงบแล้ว | ตั้งแต่ 100% ขึ้นไป | แดง |

แจ้งเตือนสี่จุด คือ ข้อความใต้ช่องจำนวนเงินตอนเลือกหมวด (เห็นก่อนจ่ายจริง),
toast ตอนบันทึกแล้วข้ามระดับ, การ์ดสรุปในหน้าโฮม และแถบเต็มในหน้าวางแผน

toast จะขึ้น**เฉพาะตอนข้ามระดับขึ้นไปเท่านั้น** บันทึกซ้ำในระดับเดิมจะไม่เตือนอีก
เพื่อไม่ให้ผู้ใช้ชินจนเลิกสนใจ ถ้าลบรายการจนลดลงต่ำกว่าเกณฑ์ ระบบจะรีเซ็ตให้เตือนใหม่ได้

การแจ้งเตือนทำงานในแอปเท่านั้น ไม่มี notification ระดับระบบปฏิบัติการ เพราะเว็บที่ไม่มีเซิร์ฟเวอร์
ปลุกหน้าที่ปิดอยู่ไม่ได้

## การเก็บข้อมูล

ข้อมูลถูกเก็บสองที่ และไม่มีการส่งออกไปที่เซิร์ฟเวอร์ใดเลย

1. **เบราว์เซอร์ของเครื่องนี้** เป็นแหล่งข้อมูลหลัก บันทึกทันทีทุกครั้ง ใช้งานได้ทุกเบราว์เซอร์
   และทำงานแบบออฟไลน์
2. **ไฟล์ CSV ในเครื่อง** เป็นชั้นเก็บประวัติ เปิดอ่านได้ด้วย Excel และ Google Sheets

บนเดสก์ท็อป Chrome และ Edge แอปเขียนไฟล์ให้อัตโนมัติหลังผู้ใช้เลือกไฟล์ครั้งแรก
บนเบราว์เซอร์อื่นและบนมือถือ ใช้ปุ่มดาวน์โหลดและนำเข้าแทน เพราะ File System Access API
ยังไม่รองรับ

### เรื่องรหัสผ่าน

**กรอกแค่ชื่อผู้ใช้ก็เริ่มใช้ได้เลย ไม่ต้องมีรหัสผ่าน** ตามที่ blueprint กำหนด
รหัสผ่านเป็นตัวเลือกเสริมที่ติ๊กเปิดได้ตอนสร้างบัญชี

ถ้าเลือกตั้ง รหัสผ่านจะถูกเก็บเป็น hash ด้วย PBKDF2 (SHA-256, 150,000 รอบ) ผ่าน WebCrypto
ไม่มีการเก็บรหัสผ่านเป็นข้อความล้วน

**รหัสผ่านนี้ใช้แยกผู้ใช้บนเครื่องเดียวกัน ไม่ใช่ระบบความปลอดภัย** ไฟล์ CSV ไม่ได้เข้ารหัส
ใครที่เข้าถึงเครื่องได้ก็เปิดอ่านผ่าน Excel ได้โดยไม่ต้องผ่านแอป
ประโยชน์จริงคือกรณีที่หลายคนใช้เครื่องเดียวกันแล้วบังเอิญตั้งชื่อผู้ใช้ซ้ำกัน

ตอนเข้าใช้งาน ถ้าชื่อนั้นไม่มีบัญชีไหนตั้งรหัสผ่านไว้ จะเข้าได้ทันที
ถ้ามีบัญชีที่ตั้งรหัสไว้ ระบบจะขอรหัสผ่าน และถ้าเว้นว่างจะเข้าบัญชีที่ไม่มีรหัสผ่านแทน

ไม่มีระบบรีเซ็ตรหัสผ่าน แต่ตั้งคำใบ้ได้ ซึ่งจะแสดงเมื่อกรอกผิดครบ 3 ครั้ง
และถ้าลืมจริงๆ ยังกู้ข้อมูลได้ด้วยการสร้างบัญชีใหม่แล้วนำเข้าไฟล์ CSV ที่เคยบันทึกไว้

### หมวดหลักและหมวดย่อย

หมวดหมู่มีสองชั้น หมวดหลักคือหมวดมาตรฐานที่มีมาให้ ส่วนหมวดย่อยคือของจริงที่ซื้อ
เช่นหมวดหลัก สุขภาพ มีหมวดย่อย พารา 35 บาท และ แก้แพ้ 80 บาท

ราคาต่อหน่วยอยู่ที่หมวดย่อย ไม่ใช่หมวดหลัก เพราะหมวดหนึ่งมีของหลายอย่างหลายราคา
หมวดย่อยใช้อิโมจิของหมวดหลักแต่ใช้ชื่อของตัวเอง และเรียงต่อจากหมวดหลักทันทีในหน้าบันทึก

สร้างได้สองทาง คือปุ่ม "+ หมวดย่อย" ในหน้าจัดการหมวดหมู่
หรือปุ่ม "อื่นๆ (พิมพ์เอง)" ในหน้าบันทึกซึ่งเลือกได้ว่าจะให้สังกัดหมวดหลักไหนหรือไม่สังกัดใคร
ถ้าไม่ตั้งชื่อหมวดย่อย จะใช้ชื่อหมวดหลักแทน ซึ่งเท่ากับเป็นการตั้งราคาให้หมวดหลักนั้นเอง

**รายการที่บันทึกเก็บทั้งชื่อหมวดหลักและชื่อหมวดย่อย** ยอดของทุกหมวดย่อยจึงยังรวมอยู่ในหมวดหลัก
ตั้งงบ "สุขภาพ" ครั้งเดียวคุมได้ทั้ง พารา และ แก้แพ้ และกราฟวงกลมก็ยังไม่แตกเป็นเศษเล็กเศษน้อย

### ราคาต่อหน่วย จำนวน และการปักหมุด

เปิด MENU แล้วกดจัดการหมวดหมู่ เพื่อตั้งค่าสามอย่างของแต่ละหมวด

- **ราคาต่อหน่วย** ตั้งไว้ครั้งเดียว เช่น พารา 35 บาท ครั้งต่อไปที่กดหมวดนี้ในหน้าบันทึก
  ช่องจำนวนเงินจะเติมให้เอง และยังพิมพ์ทับได้เสมอ
- **จำนวน** ในหน้าบันทึกมีช่องจำนวนใต้ช่องเงิน ปรับได้ทั้งพิมพ์ตัวเลขและกดปุ่มเพิ่มลด
  ซื้อ 3 ชามได้ยอดรวม 150 อัตโนมัติ ยอดที่เก็บลงข้อมูลเป็นยอดรวมเสมอ
  ส่วนจำนวนหน่วยถูกเก็บไว้ด้วย แถวรายการจึงแสดง `× 3` ให้เห็น
- **ปักหมุด** หมวดที่ปักหมุดจะขึ้นบนหน้าโฮม แยกเป็นแถวรายรับและแถวรายจ่าย
  กดชิปครั้งเดียวจะไปหน้าบันทึกพร้อมประเภท หมวด และราคาที่กรอกไว้ให้แล้ว

ถ้ายังไม่ได้ปักหมุดอะไรเลย การ์ดบนหน้าโฮมจะมีปุ่มไปหน้าบันทึกและปุ่มจัดการหมวดหมู่แทน

### หมวดหมู่ที่ตั้งเอง

กด "อื่นๆ" แล้วพิมพ์ชื่อหมวดได้เลย มีช่องติ๊ก "บันทึกเป็นหมวดใหม่" ที่เปิดไว้ให้
ถ้าติ๊กไว้หมวดนั้นจะกลายเป็นปุ่มลัดในครั้งต่อไป ถ้าไม่ติ๊กก็ใช้แค่ครั้งเดียว
ระหว่างพิมพ์ระบบจะเสนอหมวดที่เคยสร้างไว้ให้กดเลือกได้

ตอนลบหมวด ระบบจะบอกว่ามีกี่รายการที่ใช้หมวดนั้นอยู่ แล้วเปลี่ยนรายการเหล่านั้น
จาก "น้ำมัน" เป็น "อื่นๆ (น้ำมัน)" ประวัติจึงไม่เสียความหมาย และงบประมาณของหมวดนั้นก็ย้ายตามไปด้วย

### แผงคู่มือ ข้อมูลสำหรับอาจารย์ และประวัติการอัปเดต

ใน MENU มีสามแผงอ่านอย่างเดียว

- **คู่มือการใช้งาน** สำหรับผู้ใช้จริง บอกวิธีบันทึก วิธีอ่านสรุป วิธีตั้งงบ วิธีเก็บไฟล์
  และวิธีย้ายข้อมูลไปเครื่องอื่น
- **ข้อมูลสำหรับอาจารย์** ขึ้นต้นด้วยหัวข้อว่าเว็บแอปนี้พัฒนาด้วย Claude AI
  แล้วอธิบายฟีเจอร์ตามโจทย์พร้อมเหตุผลที่เลือกทำแบบนั้น ฟีเจอร์เสริมที่เพิ่มเข้ามา
  และข้อจำกัดที่รู้ตัวและยอมรับ
- **ประวัติการอัปเดต** บอกว่าแต่ละเวอร์ชันเพิ่ม ปรับ หรือลบอะไรไปบ้าง เปิดจากปุ่มในเมนู
  หรือกดที่ป้ายเลขเวอร์ชันข้างหัวข้อ MENU

เลขเวอร์ชันอ่านว่า `V N1.N2.N3` โดย N2 คือเฟส หนึ่งเฟสเท่ากับหนึ่งอัปเดต
N3 คืออัปเดตย่อยในเฟสนั้นซึ่งเริ่มที่ 0 เฟสที่แยกเป็น A และ B จึงนับเป็นอัปเดตย่อยสองครั้ง
ส่วน N1 จะเพิ่มขึ้นเมื่อ N2 จะเกิน 5 แล้วรีเซ็ต N2 กลับเป็น 1

### รายงานสรุปที่พิมพ์เป็น PDF ได้

ในหน้าสถิติ เลือกช่วงเวลาแล้วกดปุ่มสรุปเป็นรายงาน จะได้หน้าสรุปที่อ่านเหมือนสมุดบัญชี
มีหัวรายงาน ยอดรวม ตารางแยกตามหมวดพร้อมหมวดย่อย ตารางตามเวลา และรายการแบบละเอียด

ปุ่มพิมพ์เรียกหน้าต่างพิมพ์ของเครื่อง ซึ่งมีตัวเลือกบันทึกเป็น PDF อยู่แล้วทั้งบน iPhone และ Android
จึงไม่ต้องเพิ่ม library ใดเลย สไตล์สำหรับสื่อพิมพ์จะพลิกธีมมืดเป็นตัวดำบนพื้นขาว
ซ่อนแถบนำทางกับปุ่ม และกันไม่ให้ตารางขาดกลางหน้า

**รายงานเป็นสรุป ไม่ใช่การเทข้อมูลดิบ** จำนวนแถวถูกจำกัดด้วยโครงสร้าง ไม่ใช่ด้วยการตัดข้อมูลทิ้ง

| ช่วง | ตารางตามเวลา | แถวสูงสุด |
|---|---|---|
| วัน | รายการทีละรายการ | เท่าที่มีจริง |
| สัปดาห์ | สรุปรายวัน | 7 |
| เดือน | สรุปรายวัน | 31 |
| ปี | สรุปรายเดือน | 12 |

รายการทีละรายการแนบให้เฉพาะช่วงวันและสัปดาห์ ส่วนเดือนกับปีจะบอกให้เปิดไฟล์ CSV แทน
รายงานทั้งปีจึงยาวไม่กี่หน้ากระดาษเสมอ

### โอนเงินระหว่างกระเป๋า

เปิด MENU หัวข้อกระเป๋าของฉัน แล้วกดโอนเงินระหว่างกระเป๋า

**การโอนไม่นับเป็นรายรับหรือรายจ่าย** เพราะเงินยังเป็นของผู้ใช้อยู่ แค่ย้ายที่
ถ้านับตรงๆ การโอน 1,000 บาทจะทำให้ยอดรายรับและรายจ่ายของเดือนนั้นพองขึ้นข้างละ 1,000
และไปกินงบประมาณด้วย ทั้งที่ยังไม่ได้ใช้เงินเลย

| ที่ใช้ | นับรายการโอนไหม |
|---|---|
| ยอดคงเหลือของกระเป๋า | นับ |
| รายการล่าสุด | นับ |
| กราฟและอันดับหมวดในหน้าสถิติ | ไม่นับ |
| งบประมาณและการเตือน | ไม่นับ |
| ยอดรายรับรายจ่ายเดือนนี้บนหน้าโฮม | ไม่นับ แต่มีบรรทัดโอนเข้าออกแยกให้ |

เก็บเป็นรายการคู่ที่ผูกกันด้วยรหัสเดียวกัน ขาออกอยู่กระเป๋าต้นทางและขาเข้าอยู่ปลายทาง
ลบหรือแก้ขาเดียวจะมีผลกับทั้งคู่ ไม่งั้นสองกระเป๋าจะเล่าเรื่องคนละเรื่อง

### ปฏิทินรายการประจำบนหน้าโฮม

การ์ดปฏิทินแสดง **เฉพาะรายการที่ตั้งไว้ล่วงหน้า** คือกฎรายการประจำและแผนออมของเป้าหมาย
ไม่รวมรายการที่บันทึกไปแล้ว เพราะสองอย่างนี้ตอบคนละคำถาม ปฏิทินตอบว่าอะไรกำลังจะมา
ส่วนรายการที่บันทึกจริงมีหน้าสถิติกับรายการล่าสุดดูอยู่แล้ว

- **แบบเดือน** ช่องละหนึ่งวัน มีจุดสีบอกว่ามีอะไรถึงกำหนด เขียวคือรายรับ แดงคือรายจ่าย
  ทองคือการออมตามเป้าหมาย กดที่วันไหนแล้วรายละเอียดจะกางออกด้านล่าง
  ที่ต้องย่อเป็นจุดเพราะ 31 ช่องบนจอกว้าง 400px ใส่ข้อความไม่ลง
- **แบบสัปดาห์** เจ็ดแถว แสดงชื่อรายการและจำนวนเงินตรงๆ เพราะพื้นที่พอ

### รายการประจำ

ตั้งในหน้าวางแผน สำหรับรายรับหรือรายจ่ายที่เกิดซ้ำ มีสองรอบให้เลือก

- **ทุกเดือน ตามวันที่** ยึดวันที่ในปฏิทิน วันที่ 1 คือวันที่ 1 ไม่ว่าเดือนนั้นจะมี 28 หรือ 31 วัน
  ถ้าตั้งวันที่ 31 แล้วเจอเดือนที่สั้นกว่า จะเลื่อนมาเป็นวันสุดท้ายของเดือนแทน เหมาะกับเงินเดือนและค่าห้อง
- **ทุก N วัน** นับจากครั้งล่าสุด วันที่จึงค่อยๆ เลื่อนไปในปฏิทิน
  เหมาะกับค่าสมาชิกที่ให้สิทธิ์เป็นจำนวนวัน เช่นสมัคร 30 วัน ครบเมื่อไรก็จ่ายใหม่เมื่อนั้น

เว็บที่ไม่มีเซิร์ฟเวอร์ปลุกตัวเองตอนถึงกำหนดไม่ได้ ระบบจึงคำนวณตอนเปิดแอปว่ามีวันไหนค้างอยู่บ้าง
แล้วขึ้นหน้าต่างให้ติ๊กเลือกก่อนสร้างทุกครั้ง รอบที่เอาติ๊กออกจะถือว่าผ่านไปแล้วและไม่ถามซ้ำ
จำกัดการไล่ย้อนหลังไว้ที่ 60 รายการต่อกฎ เผื่อกรณีไม่ได้เปิดแอปนานมาก

รายการประจำเลือกหมวดย่อยได้ด้วย ค่าห้องกับค่าเน็ตที่อยู่ใต้ "บิล/ค่าบริการ" เหมือนกัน
จึงแยกออกจากกันได้ และแต่ละแถวบอกวันครบกำหนดถัดไปแทนที่จะบอกแค่ครั้งล่าสุด

### เป้าหมายการออม

ตั้งจำนวนเงินกับวันที่ แล้วระบบแบ่งให้ว่าต้องออมวันละเท่าไร เช่น 1,000 บาทใน 15 วัน
ได้วันละ 67 บาท ถ้าออมไม่ทันแผน การ์ดจะบอกว่าตอนนี้ต้องออมวันละเท่าไรถึงจะทัน

บันทึกด้วยการติ๊กของวันนี้ ยอดแก้ได้ก่อนติ๊ก และติ๊กวันเดิมซ้ำคือการแก้ยอดของวันนั้น
ไม่ใช่การเพิ่มอีกก้อน มีแถบเจ็ดช่องบอกว่าเจ็ดวันล่าสุดออมครบวันไหนบ้าง

**เงินออมไม่ถูกนับเป็นรายจ่าย** เพราะเงินยังไม่ได้ออกไปไหน ผู้ใช้แค่กันไว้
ถ้านับตอนออมเป็นรายจ่าย ยอดคงเหลือจะลดสองรอบ คือรอบที่กันเงินและรอบที่ใช้จริง
เงินออมจึงเก็บเป็นคนละชุดข้อมูลกับรายการธุรกรรม

| สถานะ | ความหมาย |
|---|---|
| กำลังออม | ยังออมไม่ครบ |
| ถึงเป้าแล้ว | ออมครบแล้วแม้ยังไม่ถึงวันกำหนด เงินยังอยู่ในกระเป๋า |
| ใช้เงินแล้ว | กดใช้แล้ว ระบบบันทึกเป็นรายจ่ายจริงในหมวดที่เลือก ภารกิจจบ |

หมวดที่จะใช้เงินเลือกได้ตั้งแต่ตอนตั้งเป้าหมาย หรือมาเลือกตอนออมครบก็ได้

### บัญชีและกระเป๋า

หนึ่งบัญชีมีได้หลายกระเป๋า สลับได้จากปุ่ม MENU มุมขวาบน ข้อมูลของแต่ละกระเป๋าแยกกัน
เหมาะกับการแยกเงินใช้ประจำวันออกจากเงินเก็บก้อนอื่น

ถ้าบัญชีไม่มีกระเป๋าเลย เช่นนำเข้าไฟล์ที่ไม่มีข้อมูลกระเป๋าติดมา หน้าโฮมจะแจ้งและให้กดสร้าง
ส่วนแท็บอื่นจะพากลับมาหน้าโฮมจนกว่าจะมีกระเป๋า

### การนำเข้าและการรวมข้อมูล

- ไฟล์เพิ่มแถวชนิด `saving` และคอลัมน์ `goal_id`, `status`, `plan_per_day`, `spend_category`, `spend_sub`, `paid_tx` ตั้งแต่ V1.4.4
- ไฟล์เพิ่มแถวชนิด `recurring` และคอลัมน์ `transfer_id`, `transfer_peer`, `cycle`, `cycle_value`, `last_run`, `active` ตั้งแต่ V1.4.2
- ไฟล์เพิ่มคอลัมน์ `parent` และ `sub` ต่อท้ายตั้งแต่ V1.4.1 และ `cost`, `quantity`, `pinned` ตั้งแต่ V1.3.3 ไฟล์ที่บันทึกไว้ก่อนหน้านั้นยังนำเข้าได้ตามปกติ
- รายการที่ id ซ้ำกันใช้กฎ last-write-wins ตาม `updatedAt` ถ้าเวลาเท่ากันให้ของในเครื่องชนะ
- การลบเป็นแบบ soft delete รายการที่ลบไปแล้วจะไม่ฟื้นกลับมาเมื่อนำเข้าไฟล์เก่า
- แถวที่ข้อมูลไม่ถูกต้องจะถูกข้ามพร้อมบอกเหตุผล ไม่ทำให้การนำเข้าทั้งไฟล์ล้มเหลว
- รายการที่ไม่มีกระเป๋าต้นทางจะถูกย้ายไปกระเป๋าชื่อ "รายการที่กู้คืน" แทนที่จะหายไปเงียบๆ

## ติดตั้งเป็นแอปและใช้งานออฟไลน์

ตั้งแต่ V1.4.5 แอปนี้เป็น Progressive Web App ติดตั้งลงเครื่องได้จริงทั้ง iPhone, Android
และคอมพิวเตอร์ ติดตั้งแล้วได้ไอคอนบนหน้าจอโฮม เปิดแบบเต็มจอไม่มีแถบที่อยู่เว็บ
และใช้งานได้ครบทุกหน้าโดยไม่ต้องมีอินเทอร์เน็ต

**iPhone และ iPad** เปิดด้วย Safari กดปุ่มแชร์ แล้วเลือก "เพิ่มลงในหน้าจอโฮม"
เบราว์เซอร์อื่นบน iOS ติดตั้งไม่ได้
**Android** กดปุ่มติดตั้งในแถบเชิญชวนของแอป หรือเมนูสามจุดของ Chrome แล้วเลือกติดตั้งแอป
**คอมพิวเตอร์** Chrome และ Edge มีไอคอนติดตั้งท้ายช่องที่อยู่เว็บ

### ทำไมแคชทั้งแอปไว้ตั้งแต่ติดตั้ง

`sw.js` เก็บไฟล์ทั้งหมดตอน `install` ไม่ใช่ทยอยเก็บตอนใช้ เพราะโค้ดทั้งแอปราว 350 KB
กับภาพอีก 152 KB รวมแล้วยังเล็กกว่าภาพหน้าปกเว็บทั่วไปหนึ่งใบ การเก็บทีเดียวจึงทำให้
"ใช้ออฟไลน์ได้" เป็นจริงตั้งแต่ครั้งแรกที่เปิด ไม่ใช่หลังจากผู้ใช้บังเอิญเดินครบทุกหน้าแล้ว

ชื่อแคชผูกกับเลขเวอร์ชัน โดยส่งมาทาง query string ตอน register (`sw.js?v=V1.4.5`)
แล้ว `sw.js` อ่านกลับจาก URL ของตัวเอง เลขเวอร์ชันจึงมีที่เดียวคือ `js/version.js`
ผลพลอยได้คือพอเลขเปลี่ยน URL ของ service worker ก็เปลี่ยน เบราว์เซอร์จึงเห็นว่ามีตัวใหม่เอง
พอตัวใหม่ทำงาน มันจะลบแคชชื่ออื่นทิ้งทั้งหมด ไม่มีไฟล์เก่าค้าง

**เพิ่มหรือลบไฟล์ในโปรเจกต์เมื่อไร ต้องแก้รายการ `SHELL` ใน `sw.js` ด้วยเสมอ**
ไฟล์ที่ตกหล่นจะยังใช้ได้ตอนออนไลน์และพังตอนออฟไลน์ ซึ่งเป็นวิธีที่แย่ที่สุดที่จะรู้ตัว
ชุดทดสอบเทียบรายการนี้กับไฟล์จริงในโปรเจกต์ทุกครั้ง

### ขึ้นเวอร์ชันใหม่แล้วถามก่อน

เมื่อ service worker ตัวใหม่ติดตั้งเสร็จ มันจะรออยู่เฉยๆ ไม่แทนที่ตัวเก่าเอง
แอปขึ้นแถบถามว่าจะอัปเดตเลยหรือไว้ก่อน กดอัปเดตแล้วจึงสลับและโหลดหน้าใหม่
ที่ไม่สลับให้เองทันทีเพราะผู้ใช้อาจกำลังกรอกรายการค้างอยู่ การเปลี่ยนไฟล์ใต้หน้าที่เปิดค้าง
จะทำให้สิ่งที่พิมพ์ไว้หาย

### เรื่องที่ต้องรู้เกี่ยวกับพื้นที่เก็บข้อมูล

แอปที่ติดตั้งกับหน้าเว็บในเบราว์เซอร์ใช้ที่เก็บข้อมูลของ origin เดียวกัน ข้อมูลจึงตามไปด้วย
แต่ถ้าเครื่องไหนแยกที่เก็บ ทางออกคือดาวน์โหลด CSV จากเบราว์เซอร์แล้วนำเข้าในแอปที่ติดตั้ง
และการถอนการติดตั้งจะลบข้อมูลไปด้วย จึงควรมีไฟล์ CSV เก็บไว้เสมอ

## เสียง

มีเสียงสั้นๆ สองเสียงเท่านั้น คือตอนบันทึกรายรับกับตอนบันทึกรายจ่าย
รายรับเป็นสองโน้ตไล่ขึ้น A5 ไป E6 รายจ่ายเป็นสองโน้ตไล่ลง E5 ไป A4 และเบากว่าเล็กน้อย
เป็นคู่ห้าเหมือนกันทั้งคู่ ต่างแค่ทิศทาง จึงฟังแล้วรู้ว่าเป็นแอปเดียวกันและแยกออกว่าบันทึกอะไรไป
โดยไม่ต้องมองจอ

เสียงสังเคราะห์สดด้วย WebAudio ไม่มีไฟล์เสียงในโปรเจกต์เลย ทั้งเพราะโปรเจกต์นี้ไม่มี
dependency และเพราะทุกไบต์ต้องถูกแคชไว้ใช้ออฟไลน์ด้วย ไฟล์ mp3 สองไฟล์จะกลายเป็น
ส่วนที่หนักที่สุดของแอปทันที

`AudioContext` ถูกสร้างตอนผู้ใช้แตะจอครั้งแรกเท่านั้น ไม่ใช่ตอนโหลดหน้า
เพราะเบราว์เซอร์บล็อกเสียงที่เริ่มเองโดยไม่มีการกด และบน iOS เสียงจาก WebAudio
เคารพสวิตช์ปิดเสียงของเครื่องอยู่แล้ว เปิดฟีเจอร์นี้ไว้เป็นค่าเริ่มต้นจึงไม่รบกวนใคร
ปิดได้จากสวิตช์ในหัวข้อการแสดงผลของ MENU ค่านี้จำไว้เฉพาะเครื่องนั้น ไม่ผูกกับบัญชี
และไม่ถูกส่งไปกับไฟล์ CSV

## การแสดงผลบนมือถือ

Safari บน iPhone จะซูมหน้าเว็บเข้าเองเมื่อแตะช่องกรอกที่ตัวอักษรเล็กกว่า 16px
ทุกช่องกรอกในแอปนี้จึงมีขนาดอย่างน้อย 16px ซึ่งเป็นการแก้ที่ต้นเหตุ

ใน MENU มีสวิตช์ล็อกหน้าจอไม่ให้ซูมเองอีกชั้นหนึ่ง เปิดไว้เป็นค่าเริ่มต้น
กันการซูมจากการแตะสองครั้ง ค่านี้จำไว้เฉพาะเครื่องนั้น ไม่ผูกกับบัญชี
สวิตช์นี้ไม่ได้ห้ามการหุบนิ้วซูมเอง และไม่ควรห้าม เพราะคนสายตาไม่ดีต้องใช้

เมื่อติดตั้งเป็นแอปแล้วจะไม่มีแถบเบราว์เซอร์คั่น แถบสถานะกับขีดโฮมของ iPhone
จึงทับหน้าเว็บโดยตรง หัวจอและแถบล่างเว้นระยะด้วย `env(safe-area-inset-*)` ให้พ้น
ซึ่งค่านี้จะเป็นศูนย์จนกว่า viewport meta จะมี `viewport-fit=cover` และสตริง viewport
ทั้งสองแบบที่สวิตช์ล็อกหน้าจอสลับไปมาต่างก็มีค่านี้ ไม่งั้นการปิดสวิตช์จะทำให้ระยะเว้นหายไป

## ธีมและพื้นหลัง

ทั้งแอปเป็นโทนมืดน้ำเงินเข้ม การ์ดทุกใบเป็นกระจกโปร่งแสง สีทองเป็นสีหลักของแบรนด์
ส่วนเขียวกับแดงสงวนไว้ให้รายรับ รายจ่าย และระดับงบประมาณเท่านั้น ไม่ใช้เป็นสีตกแต่ง

หน้าโฮมมีภาพพื้นหลังเต็มจอพร้อมแอนิเมชันเงินร่วงที่ค่อยๆ ช้าลงจนลอยค้างอยู่บนจอ
ส่วนแสงคือความสว่างของภาพถ่ายเองที่ไล่ขึ้นจากมืด ไม่ได้วาดแสงเพิ่มบน canvas
เพราะแสงสังเคราะห์สามชั้นเดิมตัดกันเองจนเห็นเป็นรอยต่อแข็งๆ ในเมื่อภาพต้นฉบับมีลำแสงอยู่แล้ว
การไล่ความสว่างของภาพจึงให้ผลว่า "ไฟค่อยๆ ติด" ได้ตรงกว่าและเบากว่า

เล่นเต็มความยาวครั้งแรกของแต่ละ session และเล่นสั้นลงเมื่อกลับเข้าหน้าโฮมอีก
เคารพการตั้งค่า `prefers-reduced-motion` และหยุดวาดทันทีเมื่อออกจากหน้าโฮมเพื่อไม่ให้กินแบตเตอรี่

ตัวอักษรบนการ์ด แผง และพื้นผิวทั้งหมดผ่านเกณฑ์ WCAG AA โดยวัดจากพิกเซลที่เรนเดอร์จริง
รวมภาพถ่าย ชั้นแสง และกระจก

ข้อยกเว้นที่ยังค้างอยู่คือปุ่มหลักสีเขียวที่เป็นตัวหนังสือขาว วัดได้ 2.66 ซึ่งต่ำกว่าเกณฑ์ 4.5
เป็นแบบนี้มาตั้งแต่เฟส 1 และอยู่ในรายการที่ยังไม่ได้ทำ

รวมน้ำหนักไฟล์ภาพทั้งหมด 149 KB

## ยังไม่ได้ทำ

- การซิงก์ข้ามอุปกรณ์แบบอัตโนมัติ (ย้ายไฟล์ CSV เองได้ หรือวางไว้ในโฟลเดอร์ Drive/OneDrive)
- งบประมาณย้อนหลังรายเดือน ตอนนี้เป็นงบเดียวที่ใช้ซ้ำทุกเดือน
- ส่งออกเป็น XLSX
- แก้คอนทราสต์ของปุ่มหลักสีเขียว ตัวหนังสือขาวบนพื้น `#35b37e` วัดได้ 2.66 ต้องได้ 4.5
  แก้ได้ด้วยการทำสีเขียวให้เข้มขึ้นหรือเปลี่ยนตัวหนังสือเป็นสีเข้ม ซึ่งกระทบหน้าตาทั้งแอป
- เสียงสำหรับจังหวะอื่น เช่น งบเกินหรือถึงเป้าหมาย โมดูลเสียงรองรับไว้แล้ว
- การแจ้งเตือนรายการประจำผ่าน Push Notification ซึ่งต้องมีเซิร์ฟเวอร์ จึงเกินขอบเขตโปรเจกต์นี้
